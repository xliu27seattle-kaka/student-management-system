## Findings and corrections

| Finding                                 | Before                                                                                                                                                   | Correction and regression evidence                                                                                                                                                                                                                                                                                   |
| --------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Stale roster responses                  | A refresh for the same student could overwrite a newer enrollment result. An ID comparison alone did not prevent this.                                   | Cancel the previous roster request before loading again. HTTP tests cover both record changes and refreshes of the same record.                                                                                                                                                                                      |
| Stale course search results             | An older search or a previous student's request could replace the current course options.                                                                | Cancel superseded option requests and disable selection/pagination while loading. Tests verify cancellation and retention of the latest results.                                                                                                                                                                     |
| Detail requests and cached drafts       | Rapid tab changes could leave a stale loading indicator or allow repeated detail requests to overwrite a form.                                           | Cancel the active detail request on route changes and reset loading before returning to a cached form. Tests preserve a dirty cached draft while another request is pending.                                                                                                                                         |
| Tab closing with query parameters       | Comparing the full URL with a plain record path failed for URLs containing a query string or fragment. The tab disappeared while its editor stayed open. | Use the router's path comparison while ignoring query parameters and fragments. Playwright closes and discards a dirty record opened with both.                                                                                                                                                                      |
| Invalid record URLs                     | Values such as `not-an-id`, zero, or an unsafe JavaScript integer could create unusable tabs.                                                            | Validate the route before creating an editor; redirect malformed IDs to the corresponding directory. Covered in Playwright.                                                                                                                                                                                          |
| Incorrect Node prerequisite             | The README allowed Node 22.12 even though the installed Angular packages require 22.22.3 or newer in the 22.x line.                                      | Correct the docs and package engines; declare Node types and add a separate Playwright type-check command to CI.                                                                                                                                                                                                     |
| Missing strict compilation              | Documentation described strict TypeScript, but `strict` and `strictTemplates` were absent.                                                               | Enable both and execute a production build. Playwright source is also type-checked separately.                                                                                                                                                                                                                       |
| Fractional capacity accepted by the API | Jackson could coerce a JSON value such as `1.5` into an integer before Bean Validation ran.                                                              | Disable floating-point-to-integer coercion. MockMvc verifies HTTP 400 and no inserted course.                                                                                                                                                                                                                        |
| Weak rollback example                   | The integration test used capacity zero, which is already invalid at the API boundary.                                                                   | Test a valid positive capacity below two existing enrollments, then verify all attempted edits roll back.                                                                                                                                                                                                            |
| Late browser location callback          | After choosing a city manually, an earlier pending location callback could replace it.                                                                   | Ignore location callbacks superseded by a manual choice. Playwright deliberately completes location after city selection.                                                                                                                                                                                            |
| Container startup readiness             | Starting the frontend after the backend container started did not establish API readiness.                                                               | Add API/database and frontend health checks, require backend readiness before frontend startup, and use `--wait` in the documented startup command. Local Docker startup and Nginx/API checks now pass. The CI job also runs Docker browser and persistence/reset checks, but no hosted CI result has been observed. |
| Unsupported review votes                | Four simulated “Strong pass” votes could suggest more assurance than self-review provided.                                                               | Replace votes with specific findings, evidence, and remaining limits.                                                                                                                                                                                                                                                |

Earlier corrections retained: course capacity is protected with row locks and a simultaneous last-seat test; Flyway seeds courses once; closing a dirty tab avoids a second confirmation; work-tab links use separate route segments; mobile lists keep actions visible; browser deletion checks await server success; standard Spring errors retain their HTTP status.
